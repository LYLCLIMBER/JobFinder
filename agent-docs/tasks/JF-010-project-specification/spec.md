# 当前系统行为基线

## 目标

依据当前生产代码、README 和既有任务事实，建立一份位于 `docs/` 的当前系统行为基线，作为后续测试精简和实现变更的回归参考，而不是将实现反推结果称为产品规格。

## 背景

现有需求分散在 README、功能任务 spec、handoff、verification 和生产代码中，缺少一份明确区分当前行为、已知差异与未来草案的统一文档。

## 范围

- 描述当前 `v1/find_job_page` 的产品目标、非目标和系统边界。
- 固化输入、动作、完成判定、滚动、视觉、Runner、Runtime、CLI、诊断和运行评估契约。
- 记录安全、可靠性要求和当前已知限制。
- 定义测试精简后必须保留的项目级验收场景。
- 逐项记录现有测试保护的行为、重构耐受性和删除风险。
- 明确 JF-009 分类招聘发现仍是未来草案，不写成当前能力。

## 不在范围

- 修改生产代码、测试或现有产品行为。
- 解决 evidence 校验、多模态降级或分类招聘发现等未实现能力。
- 重写现有历史任务文档。

## 安全边界

- 不读取或记录密钥、`.env` 内容、诊断产物或真实模型消息。
- 不修改相邻 `../browser-use` 或未跟踪的 JF-009 草案。

## 验收标准

- `AC-001`：`docs/current-behavior.md` 明确当前能力、非目标和系统边界。
- `AC-002`：文档覆盖当前输入输出、动作、完成、滚动、视觉、运行时、CLI、诊断和评估契约。
- `AC-003`：文档中的默认值、错误码和已实现行为与当前生产代码一致。
- `AC-004`：文档明确记录通用标题校验、点击目标安全、evidence、多模态降级、私有 DOM、虚拟滚动和诊断脱敏等已知限制。
- `AC-005`：文档定义测试精简后仍需保留的项目级验收场景和测试保留原则。
- `AC-006`：未来分类发现草案与当前 `v1/find_job_page` 契约明确分离。
- `AC-007`：Markdown 相对链接有效，文档不包含密钥或敏感运行内容。
- `AC-008`：`docs/test-protection-map.md` 覆盖全部现有测试函数，并逐项回答行为、重构耐受性和删除风险。
