# 条件视觉回退实现方案

## 目标

JobFinder 使用一个支持视觉的 LLM，在文本 DOM 不足以表达交互元素含义时，额外提供当前视口截图。典型场景是只有 CSS 背景图片、没有文字或无障碍名称的招聘入口按钮。

视觉输入是条件性的：普通页面只发送文本 DOM；当前状态存在能够可靠标注的无文本交互元素时，才发送带 selector index 标注的完整视口截图。

## 设计边界

- JobFinder 保持通用，不加入企业、域名、CSS class 或招聘 URL 特殊规则。
- 继续使用现有 `click`、`scroll`、`wait`、`done` 四种动作。
- 不执行任意 JavaScript，不提取 CSS 背景图片，不解析外部脚本。
- 不裁剪候选区域；第一版只处理一张完整当前视口截图。
- 不修改 browser-use 源码。
- 截图只增加模型观察信息，不改变成功标准。

## 运行流程

1. 获取当前 `BrowserStateSummary`，视觉开启时同时请求 DOM、`selector_map`、页面信息和完整视口截图。
2. 遍历当前 `selector_map`，找出没有文本或无障碍语义的交互元素。
3. 使用元素布局信息和当前滚动位置，将候选映射到截图像素坐标。
4. 跳过没有可靠矩形、不可见或尺寸无效的候选。
5. 在截图副本上绘制候选边框和 `[index]` 标签。
6. 有成功标注的候选时，向同一个多模态 LLM 发送文本 DOM和标注截图；否则只发送文本 DOM。
7. LLM 继续返回现有 `AgentDecision`。
8. 程序校验 click index 是否存在于当前 `selector_map`，然后执行动作。
9. 页面变化后重新获取状态；`done` 仍必须通过当前 DOM 中的岗位标题校验。

## 无文本候选

候选只从 browser-use 已经识别为交互元素的 `selector_map` 中筛选，不重复实现交互元素检测。

如果元素自身、AX 节点或后代图片提供以下任意语义，则不进入视觉候选：

- 文本内容
- `value`
- `aria-label`
- `title`
- `placeholder`
- `alt`
- AX name
- AX description

第一版只将规范化后完全为空的元素视为无文本，不使用“少于 N 个字符”的近似规则。

## 坐标和标注

优先使用 browser-use 已计算 frame 偏移的 `absolute_position`，减去当前 `page_info.scroll_x` 和 `page_info.scroll_y` 得到视口坐标，再按照截图实际尺寸与 CSS 视口尺寸的比例换算为图片像素。

候选矩形会与截图边界求交。完全不在当前视口、无布局信息、零尺寸或坐标非有限的元素会被跳过。只把成功标注的 index 作为视觉候选集合传给模型。

标注发生在内存中的截图副本上，不修改网页，不保存截图文件，不把 Base64 内容写入日志。

## 模型消息和安全边界

启用视觉且存在标注候选时，用户消息由以下部分组成：

- 当前任务、URL、标题、滚动信息和 DOM 文本。
- 已标注的 selector index 列表。
- 一张完整当前视口截图。

系统提示要求模型将截图标签视为当前 DOM 的 index，并且只能使用现有动作。程序仍然校验 click index 是否属于当前状态；`done` 不能仅依据截图通过，岗位标题必须出现在当前 DOM。

截图获取、解码、坐标计算或模型多模态调用失败时，不执行猜测点击，回退到纯文本消息或当前已有的错误处理。

## 配置

`JobPageFinder` 增加 `use_vision=False` 参数，默认保持现有纯文本行为。调用方使用支持视觉的模型时显式传入 `use_vision=True`。

## 测试

- 无文本、无 AX 语义的交互元素会被识别为候选。
- 有文本、ARIA、AX 或图片 alt 的交互元素不会被识别为候选。
- 页面滚动和设备像素比下坐标转换正确。
- 无效或视口外矩形会被跳过。
- 标注图包含正确的 selector index。
- 没有候选或截图失败时只发送文本消息。
- 有候选时发送一个 PNG 图片内容块，并继续使用 `AgentDecision`。
- 现有岗位完成校验、点击校验和浏览器清理行为不变。
- 使用本地静态页面验证完整链路；Kuro 作为真实网站集成验证，不作为稳定单元测试依赖。
